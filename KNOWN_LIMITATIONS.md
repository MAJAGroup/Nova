# Known limitations and outstanding work

> Desktop is now the primary product (`npm start`), following the user's updated preference. It uses local Electron Chromium views without starting a server. Unless explicitly marked desktop, the detailed service/agent/deployment sections below describe the optional remote mode (`npm run start:server`). See [README.md](README.md) and [docs/DESKTOP.md](docs/DESKTOP.md) for native behavior and limitations.


This is a working first single-host implementation, not every capability in the master specification.

- JPEG frame delivery has no browser audio, synchronized multimedia, microphone/camera forwarding, drag selection, right-click menus, file upload/download approval UX, or full touch gesture forwarding. Video frames may appear, but this is not a verified media streaming path. Remote viewport resizing is available in the typed action protocol; automatic UI viewport adaptation is pending.
- Chromium contexts isolate cookies but share a browser process. Public adversarial multi-tenant hosting requires separate workers, OS/network egress restrictions, and independent review. Docker configuration is supplied but container deployment was not verified; the primary release target became the desktop app.
- SQLite and in-process scheduling support one application process. There are no PostgreSQL/Redis services, distributed job leases, horizontal scaling, memory-pressure scheduling, or browser-process-specific accounting. User and browser quotas are intentionally small.
- Client disconnect preserves live tasks with explicit background permission. Server restart pauses interrupted tasks for user inspection/resume. URLs, cookies, local storage and navigation graph recover; JS heaps, session storage and native browser back/forward stacks do not. This is not lossless recovery.
- The page structure is bounded visible DOM extraction, not the full AX tree. Cross-origin frames, shadow roots, complex select widgets and image descriptions need dedicated support. Automated axe results do not certify WCAG conformance; a human screen-reader audit is outstanding.
- Autonomous tasks can use a separate workspace and context, but multi-topic decomposition, combined summaries across tasks, vision tools, native provider tool-calling negotiation, provider/model discovery and live model quality evaluation remain outstanding. Current adapters require JSON action output. No live model credentials were available during verification.
- All modifying AI tools require approval. The conservative policy means even ordinary agent navigation/fill/click steps pause. Approval hashes intentionally expire if the observed page changes; highly dynamic pages may require frequent replanning.
- Up to four panes are represented; UI supports split balance for two. Groups/clustering, graph virtualization beyond a 2,000-visit response cap, user-managed constellations, graph expand/collapse, tab duplication, full layout maximize/restore, and archive administration are pending. Named two-site and explicit URL commands work; ambiguous “three websites” commands require destinations.
- Per-session state snapshots are sent periodically rather than delta events. Sequence numbers reset on reconnect, which replaces state with a full owned snapshot. Persistent notification delivery and external notifications are absent.
- No password reset, email verification, MFA, SSO, administrator UI, or account recovery. Registration can be disabled. Sessions expire after seven days without sliding renewal. The terminal client requires HTTPS for remote use and lacks realtime presence tracking.
- Some websites block automation, require CAPTCHA, DRM/media integration, downloads, permissions or popup behavior that is unsupported. The agent does not bypass website access controls. Public-site smoke tests are optional and were not used as deterministic acceptance evidence.
- Dependency audit found moderate upstream advisories during installation. Review `npm audit` before deployment; legacy Electron dependencies are included in the root manifest. Container scanning and release hardening are pending.
- Test coverage focuses on functional vertical slices, isolation and approval invariants. Exhaustive malicious-site testing, stress/load capacity, model-provider quality and full accessibility audit remain outstanding.
